# Resubmission Strategies Guide

## Overview

Not all funded proposals are funded on the first submission. Resubmission is a normal part of the grant process. A well-crafted resubmission that thoughtfully addresses reviewer feedback has a significantly higher chance of success.

## NIH Resubmission (A1)

### The A1 Process

1. **Receive A0 reviews**: Study section summary statement
2. **Analyze feedback**: Identify major and minor criticisms
3. **Decide to resubmit**: Only if you can meaningfully address the concerns
4. **Write Introduction to Resubmission**: 1-page response to reviewers
5. **Revise the application**: Address each criticism
6. **Submit A1**: Typically within 37 months of A0

### Introduction to Resubmission (1 Page Maximum)

**Structure**:

```
RESPONSE TO REVIEWERS

We thank the reviewers for their constructive feedback on our A0 application 
[R01 MH-XXXXXX-01]. We have carefully considered each comment and have made 
substantial revisions to address all concerns. Below we summarize the major 
changes made in response to the review.

MAJOR CONCERNS ADDRESSED

1. [Reviewer concern about X]
   Response: We have addressed this by [specific change]. [Brief explanation 
   of what was changed and where in the application it can be found.]

2. [Reviewer concern about Y]
   Response: We have [specific change]. This is described in detail on page X 
   of the Research Strategy.

3. [Reviewer concern about Z]
   Response: We have added [new data/preliminary results/additional experiment] 
   to address this concern. See [location in application].

MINOR CONCERNS ADDRESSED

We have also addressed all minor concerns raised by the reviewers, including:
- [Minor concern 1]: [Brief response]
- [Minor concern 2]: [Brief response]

SUMMARY OF CHANGES

- [Major change 1]
- [Major change 2]
- [Major change 3]
```

### Writing Strategies for A1

1. **Be specific**: Reference exact reviewer comments and your responses
2. **Be concise**: 1 page maximum; reviewers read many applications
3. **Be respectful**: Thank reviewers for their feedback
4. **Be substantive**: Show real changes, not just cosmetic edits
5. **Point to changes**: Direct reviewers to where changes appear in the application
6. **Address every concern**: Don't ignore any criticism, even minor ones

### Decision Tree: Should You Resubmit?

```
Is the impact score < 30?
├── YES: Strong candidate for resubmission
│   ├── Can you address the major concerns?
│   │   ├── YES: Resubmit as A1
│   │   └── NO: Consider new direction or different institute
│   └── Are the concerns fixable (vs. fundamental disagreement)?
│       ├── YES: Resubmit with changes
│       └── NO: Consider new application
└── NO: Impact score > 30
    ├── Are the concerns addressable?
    │   ├── YES: Consider substantial revision
    │   └── NO: Consider new direction
    └── Is the payline likely to include your score?
        ├── YES: Wait for council
        └── NO: Resubmit or submit new
```

### Common A1 Mistakes

1. **Not addressing all concerns**: Leaving out reviewer criticisms
2. **Cosmetic changes only**: Rewording without substantive improvement
3. **Too defensive**: Arguing with reviewers instead of addressing concerns
4. **Exceeding page limit**: Introduction must be 1 page
5. **Not pointing to changes**: Reviewers can't find what you changed
6. **Same application**: Submitting essentially the same proposal

## NSF Resubmission

### NSF's Approach

- **No formal resubmission category**: NSF does not have an A0/A1 system
- **Resubmission treated as new proposal**: Same review process
- **No Introduction to Resubmission**: But you can address prior feedback

### Strategies for NSF Resubmission

1. **Incorporate feedback**: Address reviewer concerns in the body of the proposal
2. **Update the literature**: Add recent publications
3. **Strengthen preliminary data**: Add new results since last submission
4. **Improve broader impacts**: Address any weakness in broader impacts
5. **Check program fit**: Ensure you're submitting to the right program
6. **Contact program officer**: Discuss whether resubmission is appropriate

### How to Address Prior NSF Reviews

**In the Project Description**:
- Don't explicitly mention prior reviews
- Address concerns naturally in the text
- If reviewers missed something, make it more prominent
- If reviewers found something unclear, rewrite for clarity

**In a Cover Letter** (optional):
- Brief note that this is a resubmission
- Highlight key changes from prior submission
- Ask for specific reviewers if appropriate

## DOE Resubmission

### DOE's Approach

- **Similar to NSF**: No formal resubmission category
- **Program-specific**: Some programs accept resubmissions, others don't
- **Contact program officer**: Always check before resubmitting

### Strategies for DOE Resubmission

1. **Address technical concerns**: Strengthen the technical approach
2. **Update TRL assessment**: Show progress since last submission
3. **Strengthen team**: Add expertise that was lacking
4. **Improve cost sharing**: If applicable, increase institutional commitment
5. **Align with priorities**: Ensure alignment with current DOE priorities

## DARPA Resubmission

### DARPA's Approach

- **BAA-specific**: Each BAA has its own resubmission rules
- **Program changes**: DARPA programs change frequently
- **New program manager**: A new PM may have different priorities

### Strategies for DARPA Resubmission

1. **Check program status**: Is the program still active?
2. **Contact PM**: Discuss whether resubmission is appropriate
3. **Address DARPA-hard**: Ensure the proposal passes the "DARPA-hard" test
4. **Strengthen metrics**: Add more quantitative go/no-go criteria
5. **Improve transition plan**: Address any weaknesses in transition strategy

## General Resubmission Strategies

### Analyzing Reviewer Feedback

1. **Read all reviews**: Don't just focus on the harshest critic
2. **Identify patterns**: If multiple reviewers mention the same issue, it's critical
3. **Categorize concerns**:
   - **Fundamental**: Core approach or concept is questioned
   - **Methodological**: Specific methods need improvement
   - **Presentation**: Writing or organization issues
   - **Minor**: Small issues that are easy to fix
4. **Prioritize**: Address fundamental and methodological concerns first

### Making Changes Visible

1. **Track changes**: Use colored text or bold for major changes
2. **Summary of changes**: Include in cover letter or introduction
3. **Page references**: Direct reviewers to specific pages
4. **Before/after**: Show what was changed and why

### When NOT to Resubmit

1. **Fundamental disagreement**: Reviewers disagree with the core premise
2. **Wrong program**: The project doesn't fit the funding mechanism
3. **Significant changes needed**: The project would be essentially new
4. **Better opportunities**: A different mechanism is more appropriate
5. **Time constraints**: Can't make meaningful improvements in the timeline

### Tracking Changes

**For NIH A1**:
- Highlight changes in the text (use bold or colored text)
- Reference changes in the Introduction to Resubmission
- Update the timeline and budget

**For NSF/DOE**:
- Subtly integrate changes
- Update preliminary data and references
- Improve writing and organization
