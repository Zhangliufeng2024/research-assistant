## ⚠️ 事故与恢复（重要教训）

**我在本仓库跑 `git stash push` 导致 `.git` 一度损坏**：stash 触发 repack，git 删除旧
`pack-fd82b02….pack`，被宿主环境的 safe-delete 守卫移进回收站，随后 stash 因对象缺失
中止（"fatal: not a valid object"），只剩孤立 `.idx`；`.git/refs/` 目录也一并消失，
git 报 "not a git repository"。

恢复过程（已成功）：

1. 从 `D:\$RECYCLE.BIN\S-1-5-21-3305779208-…\$R00QIOL.pack` 找回 .pack 放回 `.git/objects/pack/`
2. `mkdir -p .git/refs/{heads,tags,remotes/origin}`
3. 用 `GIT_HTTP_SSL_BACKEND=openssl`（**默认 schannel 连不上 GitHub**）`git fetch origin` 补齐缺失对象

**教训（下次务必遵守）**：

- **在这个环境里不要对 `.git` 跑会重写对象的命令**（stash/gc/repack/prune）。
  要暂存改动优先用 `git diff > patch` 或复制文件，而不是 `git stash`。
- **git 访问 GitHub 必须带 `GIT_HTTP_SSL_BACKEND=openssl`**，默认后端报
  "Failed to connect to github.com:443"（curl 正常，是 git 的 schannel 后端问题）。
- 环境的删除守卫会把 git 内部删除路由到回收站并 fail-closed，破坏 git 的原子性假设。
