## 四个"环境性失败"全部修复（2026-08-29，Windows 主场景）

- **GBK 三连（Bug A 真缺陷）**：`decode_process_output` 的兜底用
  `locale.getpreferredencoding(False)`，在 Python 3.13 UTF-8 模式下它返回
  **utf-8**——兜底链退化成 utf-8→utf-8，GBK 照样乱码。修法：新增
  `_windows_ansi_codec()`，`ctypes.windll.kernel32.GetACP()` 显式向系统要
  ANSI 代码页（中文 Windows=936 → `cp936`），非 Windows 返回 None。
  兜底顺序：utf-8 strict → ANSI 代码页 → preferred → utf-8 replace。
  **教训：Windows 上的本地编码绝不能信 locale API，要 GetACP/GetOEMCP。**
- **路径含空格（真实产品缺陷）**：`externalize_tool_result` 的指针消息
  `saved to: {path}` 不带引号，工作区路径含空格（如 `D:\vscode files\`）
  时模型只能拿到被截断的残缺路径，`read_file` 必然失败——"外置产物永远
  读不回来"。修法：指针消息给路径**加引号**，同时 `file_ops` 五个工具
  （read/write/edit/glob/grep）入口统一 `_unquote_path()` 剥包裹引号
  （模型常自带引号回传路径）。单跑时该测试"通过"是因为默认 tmp_path 在
  `C:\Users\...`（无空格），只有 `--basetemp` 指进工作区才暴露——
  **测试环境掩盖真实缺陷的又一例**。
- **重要：同一 basetemp 连跑 3 次以上会出现成批 `SystemError at setup`**——
  这是 pytest tmp_path 保留策略（清旧目录）撞上 safe-delete shim（阈值 50）
  的**沙箱伪影，不是代码缺陷**。规避：每次全量跑用全新 basetemp
  （`.pytest_tmp_<时间戳>`，已被 gitignore 覆盖）。
